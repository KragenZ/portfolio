AI Property Assistant — RAG Architecture

How I engineered a conversational property search chatbot over 500 Ames Housing records using LangChain, HuggingFace MiniLM, FAISS vector retrieval, and Gemini reasoning.

Project Type Retrieval-Augmented Generation
Primary Dataset 500 Ames Housing Listings
Embeddings Model HuggingFace MiniLM
Vector Store FAISS (Top-5 Retrieval)
LLM Reasoning Gemini (Context Grounded)

The Challenge

Traditional real estate platforms rely strictly on relational database queries and rigid dropdown UI filters (e.g., exact square footage brackets, discrete bedroom selectors, fixed price bands). When buyers search with nuanced natural language — such as "A charming 3-bedroom home under $200k with good yard space" — keyword-matching engines frequently fail because they cannot capture semantic intent.

Conversely, asking a standard large language model (LLM) about property listings results in hallucinations, fabricated inventory, or outdated pricing.

Engineering Objective

Build an end-to-end Retrieval-Augmented Generation (RAG) system that indexes real listing data, executes millisecond vector similarity queries, and produces strictly grounded responses with transparent relevance scoring and latency telemetry.

Implementation Highlights

1. Vector Search with FAISS

Converted 500 tabular property records into dense text passages containing neighborhood traits, square footage, bedroom/bathroom configurations, and historical sale prices. Used HuggingFace's all-MiniLM-L6-v2 to produce 384-dimensional embeddings, loaded into an in-memory FAISS vector index for sub-15ms nearest-neighbor queries.

2. Context Grounding with Gemini

Engineered structured prompt templates via LangChain that restrict Gemini's response strictly to retrieved facts from the top 5 candidates. The system details why each candidate matches the buyer's query, highlights trade-offs, and retains conversational context for follow-up inquiries.

Telemetry & UI Explainability

To give users transparency into the RAG pipeline's internal operations, the Streamlit interface incorporates real-time diagnostic telemetry:

  • Per-Query Relevance Scoring: Displays the cosine similarity distance between the user query embedding and each retrieved candidate.
  • Latency Telemetry: Breaks down total response latency into vector search time vs. LLM token generation time.
  • Retrieved Context Inspector: Allows users to expand the exact raw data chunk provided to the LLM to verify factual accuracy.
